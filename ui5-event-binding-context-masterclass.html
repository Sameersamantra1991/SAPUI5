2. What is oEvent?

LEVEL 1 
<!-- XML View -->
<Button text="View" press=".onViewProduct" />
// Controller.js
onViewProduct: function (oEvent) {
}

✅ oEvent IS

  • An event object created by UI5
  • A package of info: who fired + what happened + extra params
  • Passed automatically: onViewProduct(oEvent)

⛔ oEvent is NOT

  • NOT the button itself
  • NOT the data
  • NOT the model
Beginner warning: oEvent ≠ button. To get the button you must call oEvent.getSource().

4. getParent() — Who contains this control?

LEVEL 4 
const oButton = oEvent.getSource();
const oParent = oButton.getParent();
<!-- Hierarchy -->
Table
 └─ ColumnListItem  (the row)
     └─ HBox (cells wrapper if used)
         └─ Button  (you clicked here)

Button → getParent()

Returns HBox (or cells container / ColumnListItem depending on XML).

HBox → getParent()

Returns ColumnListItem (the row).

Fragile: getParent().getParent() breaks if you add/remove an HBox/VBox in XML. Prefer oEvent.getSource().getBindingContext() — it doesn't care about hierarchy because the button inherits the row's context.
Rule: Use binding context when possible. Use getParent() only when you truly need layout navigation (e.g., find sibling control).

5. Binding — connecting UI to data (absolute beginner)

LEVEL 5 
<Table items="{/Products}">

{/Products} means: bind the items aggregation to the /Products array in the default model, root (/).

{
  "Products": [
    { "id": 1, "title": "Laptop", "price": 50000, "category": "Electronics" },
    { "id": 2, "title": "Phone", "price": 30000, "category": "Electronics" }
  ]
}
UI5 loops the array automatically: 1 array entry = 1 row (ColumnListItem). Inside the row, {title} means "relative to my row's object". That's why you write {id} not {/Products/0/id}.
WordMeaning (simple)
BindingThe live link between control property/aggregation and model data
Binding ContextThe row's "address" e.g. /Products/1
ControlUI element (Table, Button, Input, Text)
ModelThe data container (JSON/OData)

Why 5 columns + 5 cells? UI5 pairs them by index: Column[0] is header for cells[0], etc. Template ColumnListItem is cloned per product — you write it once, UI5 repeats it.

14. oEvent.getParameter() — event-specific info

LEVEL 3
Key accuracy rule: Parameters depend on the control + event. Check API docs for each event. Not every event has the same params.

Input — change

<Input change=".onInputChange" />

onComboChange: function (oEvent) {
  const oSel = oEvent.getParameter("selectedItem");
  const sKey = oSel && oSel.getKey();
}

16. Main Scenario: Button inside Table Row (line by line)

onViewProduct: function (oEvent) {
  const oButton = oEvent.getSource();      // 1. clicked Button
  const oContext = oButton.getBindingContext(); // 2. row address
  const oProduct = oContext.getObject();       // 3. real data

👆 Click a step.
Why does oButton.getBindingContext() work even though the button itself has no items="{...}"? Because contexts propagate down: Row has context → children inherit it.

17. Alternative via getParent() (and why shorter is better)

onViewProduct: function (oEvent) {
  const oButton = oEvent.getSource();
  const oRow = oButton.getParent(); // assumes parent IS the row!
  const oContext = oRow.getBindingContext();
  const oProduct = oContext.getObject();
}
Works only if parent really is ColumnListItem. If Button is wrapped in HBox/VBox, you need getParent().getParent(). XML change = broken code.
Preferred (cleaner): const oContext = oEvent.getSource().getBindingContext(); — independent of layout hierarchy.

21A. ⭐ INSIDE vs OUTSIDE — the one big idea

MOST IMPORTANT NEW CONCEPT READ THIS FIRST

✅ Button INSIDE row (cells)

Row = ColumnListItem with context /Products/1 → Button inherits it.
oEvent.getSource().getBindingContext() ✅ works.

<Table items="{/Products}">
  <ColumnListItem>
    <cells>
      <Text text="{title}"/>
      <Button text="View" press=".onViewProduct"/>
    </cells>
  </ColumnListItem>
</Table>

⛔ Button OUTSIDE table (toolbar / header / footer)

Button lives in Toolbar / VBox / Page footer — no row above it → NO inherited context.
oEvent.getSource().getBindingContext() → null ❌

<VBox>
  <Toolbar>
    <Button text="View Selected" press=".onViewOutside"/>
  </Toolbar>
  <Table id="productsTable" items="{/Products}"/>
</VBox>
Golden rule: INSIDE → ask the button for context (getSource().getBindingContext()). OUTSIDE → ask the table for selection (this.byId("productsTable").getSelectedItem()). Mixing them = null.getObject() → TypeError.
QuestionButton INSIDE rowButton OUTSIDE table
Where is context?On the button itself (inherited)On the table's selected row(s) only
Get data how?oEvent.getSource().getBindingContext().getObject()this.byId("tbl").getSelectedItem().getBindingContext().getObject()
If nothing clicked/selected?Impossible — click implies a rowgetSelectedItem() === null → must guard!
Table mode needed?No (mode="None" is fine)Yes — SingleSelect / SingleSelectMaster / MultiSelect
Multi-row action?One row at a timegetSelectedItems() / getSelectedContexts() loop
Memory hook: INSIDE = "Who clicked ME?" → getSource. OUTSIDE = "What is SELECTED in the TABLE?" → byId + getSelectedItem.

21B. View / Edit / Delete button OUTSIDE table (single select)

MOST COMMON REAL APP

The standard Fiori pattern: table with mode="SingleSelectMaster" + View/Edit/Delete buttons in a toolbar above or footer below the table.

<VBox>
  <Toolbar>
    <Title text="Products"/>
    <ToolbarSpacer/>
    <Button text="View" press=".onViewOutside"/>
    <Button icon="sap-icon://edit" press=".onEditOutside"/>
    <Button icon="sap-icon://delete" press=".onDeleteOutside"/>
  </Toolbar>
  <Table id="productsTable" items="{/Products}" mode="SingleSelectMaster">
    <columns>... ID / Title / Price ...</columns>
    <items><ColumnListItem><cells>
      <Text text="{id}"/><Text text="{title}"/><Text text="{price}"/>
    </cells></ColumnListItem></items>
  </Table>
</VBox>
onViewOutside: function (oEvent) {
  // 1. OUTSIDE button → NO row context. Ignore oEvent.getSource() for data!
  const oTable = this.byId("productsTable");
  const oItem = oTable.getSelectedItem(); // ColumnListItem or null
  if (!oItem) {
    MessageToast.show("Select a row first");
    return;
  }
  const oContext = oItem.getBindingContext();
  const oProduct = oContext.getObject();
  MessageBox.show(oProduct.title + " – " + oProduct.price);
},
onDeleteOutside: function (oEvent) {
  const oTable = this.byId("productsTable");
  const oItem = oTable.getSelectedItem();
  if (!oItem) { MessageToast.show("Select a row to delete"); return; }
  const sPath = oItem.getBindingContext().getPath(); // "/Products/1"
  // → remove entry at sPath from JSONModel / call OData remove(sPath)
}

✅ Correct chain (outside)

this.byId("tbl") → getSelectedItem() → getBindingContext() → getObject()/getPath()

⛔ Wrong (outside)

oEvent.getSource().getBindingContext() → null → null.getObject() crashes. Source is the toolbar button, not a row.

mode matters: without mode="SingleSelectMaster" (or SingleSelect / MultiSelect) the table has no selection and getSelectedItem() doesn't exist / always returns null. Default mode="None" = no selection possible.
Navigation with outside button: identical after you have the path — oRouter.navTo("detail", {productPath: encodeURIComponent(sPath)}). Only the first two lines differ (table lookup vs source).

21C. Buttons OUTSIDE + multi-select (bulk actions)

<Table id="productsTable" items="{/Products}" mode="MultiSelect"> ... </Table>
<Button text="Delete Selected" press=".onBulkDelete"/>
<Button text="Export Selected" press=".onBulkExport"/>
onBulkDelete: function (oEvent) {
  const oTable = this.byId("productsTable");
  const aItems = oTable.getSelectedItems(); // array of ColumnListItem
  if (!aItems.length) { MessageToast.show("Select at least one row"); return; }
  const aProducts = aItems.map(function(oItem){
    return oItem.getBindingContext().getObject();
  });
  const aPaths = aItems.map(function(oItem){
    return oItem.getBindingContext().getPath();
  });
  // aProducts → [{id:2,...},{id:3,...}]  aPaths → ["/Products/1","/Products/2"]
},
// Shortcut: contexts directly (no items needed)
onBulkExport: function (oEvent) {
  const aContexts = this.byId("productsTable").getSelectedContexts();
  const aData = aContexts.map(function(oCtx){ return oCtx.getObject(); });
}
API (table)ReturnsUse when
getSelectedItem()One ColumnListItem or nullSingleSelect + outside View/Edit/Delete

21D. No-selection guard — the crash every beginner hits

Crash: oItem.getBindingContext() where oItem === null → TypeError: Cannot read properties of null. Happens when user presses an outside View/Delete button without selecting any row.
// ❌ CRASHES when nothing selected
const oItem = this.byId("productsTable").getSelectedItem();
const oProduct = oItem.getBindingContext().getObject(); // 💥 null!
// ✅ SAFE pattern (copy-paste this)
onViewOutsideSafe: function (oEvent) {
  const oItem = this.byId("productsTable").getSelectedItem();
  if (!oItem) {
    MessageToast.show("Please select a product first");
    return; // stop here
  }
  const oProduct = oItem.getBindingContext().getObject();
  // ... continue with oProduct
}

Bonus UX: disable button until selection

<Table selectionChange=".onSelChange" ...>
<Button id="viewBtn" enabled="false" .../>
onSelChange: function (oEvent) {
  const bHas = !!this.byId("productsTable").getSelectedItem();
  this.byId("viewBtn").setEnabled(bHas);
}

Multi-select guard

const aItems = oTable.getSelectedItems();
if (!aItems.length) {
  MessageToast.show("Select at least one row");
  return;
}

Note: getSelectedItems() returns [] (never null) → check .length. getSelectedItem() returns null → check truthiness.

21E. Toolbar buttons that NEVER have context (Add / Search / Refresh)

Buttons in headerToolbar (Add, Search, Refresh, Filter) operate on the whole table/model, not one row. Don't call getBindingContext() on them — use byId + getModel + binding.

<Table id="productsTable" items="{/Products}">
  <headerToolbar><Toolbar>
    <SearchField search=".onSearch"/>
    <Button text="Add" press=".onAdd"/>
    <Button icon="sap-icon://refresh" press=".onRefresh"/>
  </Toolbar></headerToolbar>
</Table>
onAdd: function (oEvent) {
  // No row → work with the MODEL directly
  const oModel = this.getView().getModel();
  const aProducts = oModel.getProperty("/Products");
  aProducts.push({ id: Date.now(), title: "New", price: 0 });
  oModel.setProperty("/Products", aProducts);
},
onSearch: function (oEvent) {
  const sQ = oEvent.getParameter("query"); // SearchField param, NOT context
  const oBinding = this.byId("productsTable").getBinding("items");
  oBinding.filter([new Filter("title", "Contains", sQ)]);
},
onRefresh: function (oEvent) {
  this.byId("productsTable").getBinding("items").refresh();
}
Pattern: toolbar press → oEvent.getSource() is just the toolbar button (useless for data) → switch to this.byId("table").getBinding("items") or this.getView().getModel().

26. JSONModel vs OData V2/V4 (beginner-safe intro)

🗂️ JSONModel

  • Client-side object
  • oModel.getData() works
  • getObject()/getProperty() read local data
  • Great for learning

🌐 ODataModel (V2/V4)

  • Server-driven, async
  • Do NOT assume getData() exists same way
  • Context may need to load; use bindings + events
  • V4 contexts have different APIs in places
Don't assume oModel.getData() works for every model. For OData, rely on contexts/bindings, not raw data dumps.

Controller.js 
onViewProduct: function (oEvent) {
  const oProduct = oEvent.getSource().getBindingContext().getObject();
  MessageBox.show(oProduct.title + " – " + oProduct.price);
},
onRowSelect: function (oEvent) {
  const oItem = oEvent.getParameter("listItem");
  const oProduct = oItem.getBindingContext().getObject();
},
onSearch: function (oEvent) {
  const sQ = oEvent.getParameter("query");
  // filter table binding by title
},
onDeleteProduct: function (oEvent) {
  const sPath = oEvent.getSource().getBindingContext().getPath();
  // remove /Products entry at sPath from JSONModel
}
Every handler follows the same rhythm: source → context → object/path → action. Toolbar Add/Search buttons have no row context — use byId/table binding there, not getBindingContext().

Gap fill: Add + List vs Table selection NEW

onAdd: function (oEvent) {
  // toolbar button → NO row context! Create new entry in model.
  const oModel = this.getView().getModel();
  const aProducts = oModel.getProperty("/Products");
  aProducts.push({ id: Date.now(), title: "New", price: 0, category: "General" });
  oModel.setProperty("/Products", aProducts);
},
onRowSelectTable: function (oEvent) {
  // sap.m.Table selectionChange → listItem param (same as List)
  const oItem = oEvent.getParameter("listItem");
}
List vs Table selection: both sap.m.List and sap.m.Table fire selectionChange with listItem param. Table also supports mode="SingleSelectMaster" + getSelectedItem() via this.byId("tbl").getSelectedItem().
