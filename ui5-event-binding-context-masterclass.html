1. Big Picture: What happens when I click a button?

Beginner mental model. Click each step:

👆 Click any step above to learn what it is.
One sentence: User clicks → UI5 creates an oEvent object → getSource() gives you the Button control → getBindingContext() gives you the address of the row's data → getObject() gives you the real business data.

2. What is oEvent?

LEVEL 1 
<!-- XML View -->
<Button text="View" press=".onViewProduct" />
// Controller.js
onViewProduct: function (oEvent) {
}

✅ oEvent IS

  • An event object created by UI5
  • A package of info: who fired + what happened + extra params
  • Passed automatically: onViewProduct(oEvent)

⛔ oEvent is NOT

  • NOT the button itself
  • NOT the data
  • NOT the model
Beginner warning: oEvent ≠ button. To get the button you must call oEvent.getSource().
User clicks button
↓
UI5 creates event info
↓
UI5 calls onViewProduct(oEvent)

4. getParent() — Who contains this control?

LEVEL 4 
const oButton = oEvent.getSource();
const oParent = oButton.getParent();
<!-- Hierarchy -->
Table
 └─ ColumnListItem  (the row)
     └─ HBox (cells wrapper if used)
         └─ Button  (you clicked here)

Button → getParent()

Returns HBox (or cells container / ColumnListItem depending on XML).

HBox → getParent()

Returns ColumnListItem (the row).

Fragile: getParent().getParent() breaks if you add/remove an HBox/VBox in XML. Prefer oEvent.getSource().getBindingContext() — it doesn't care about hierarchy because the button inherits the row's context.
Rule: Use binding context when possible. Use getParent() only when you truly need layout navigation (e.g., find sibling control).

5. Binding — connecting UI to data (absolute beginner)

LEVEL 5 
<Table items="{/Products}">

{/Products} means: bind the items aggregation to the /Products array in the default model, root (/).

{
  "Products": [
    { "id": 1, "title": "Laptop", "price": 50000, "category": "Electronics" },
    { "id": 2, "title": "Phone", "price": 30000, "category": "Electronics" }
  ]
}
UI5 loops the array automatically: 1 array entry = 1 row (ColumnListItem). Inside the row, {title} means "relative to my row's object". That's why you write {id} not {/Products/0/id}.
WordMeaning (simple)
BindingThe live link between control property/aggregation and model data
Binding ContextThe row's "address" e.g. /Products/1
ControlUI element (Table, Button, Input, Text)
ModelThe data container (JSON/OData)

6. Complete Table Example

<Table id="productsTable" items="{/Products}">
  <columns>
    <Column><Text text="ID"/></Column>
    <Column><Text text="Title"/></Column>
    <Column><Text text="Price"/></Column>
    <Column><Text text="Category"/></Column>
    <Column><Text text="Actions"/></Column>
  </columns>
  <items>
    <ColumnListItem>
      <cells>
        <Text text="{id}"/>
        <Text text="{title}"/>
        <Text text="{price}"/>
        <Text text="{category}"/>
        <Button text="View" press=".onViewProduct"/>
      </cells>
    </ColumnListItem>
  </items>
</Table>
Why 5 columns + 5 cells? UI5 pairs them by index: Column[0] is header for cells[0], etc. Template ColumnListItem is cloned per product — you write it once, UI5 repeats it.

7. Table Data Flow → Rows → Contexts

Products
├── Product 0  →  ColumnListItem (Row 1)  →  context /Products/0
├── Product 1  →  ColumnListItem (Row 2)  →  context /Products/1
└── Product 2  →  ColumnListItem (Row 3)  →  context /Products/2
Binding context = control's connection/address to one piece of model data. Row 2 doesn't store the product — it stores a pointer /Products/1. Children (Texts, Buttons) inherit it.

13. this.byId() vs getSource()

LEVEL 11 
const oInput = this.byId("productNameInput");
MeaningExample
oEvent.getSource()Control that fired this eventWhich View button was clicked?
this.byId("...")Control with this view ID (anywhere in view)Get search field / form input / dialog
IDs are prefixed by view ID at runtime (__xmlview0--productNameInput). Always use this.byId(), never document.getElementById.

14. oEvent.getParameter() — event-specific info

LEVEL 3
Key accuracy rule: Parameters depend on the control + event. Check API docs for each event. Not every event has the same params.

Input — change

<Input change=".onInputChange" />
onInputChange: function (oEvent) {
  const sValue = oEvent.getParameter("value");
}

getSource() → Input control. getParameter("value") → typed text.

CheckBox — select

<CheckBox select=".onSelect" />
onSelect: function (oEvent) {
  const bSelected = oEvent.getParameter("selected"); // true/false
}

List — selectionChange

<List selectionChange=".onSelectionChange">
onSelectionChange: function (oEvent) {
  const oItem = oEvent.getParameter("listItem");
  const oContext = oItem.getBindingContext();
  const oData = oContext.getObject();
}

ComboBox — change

onComboChange: function (oEvent) {
  const oSel = oEvent.getParameter("selectedItem");
  const sKey = oSel && oSel.getKey();
}
Always guard: user may clear ComboBox → selectedItem is null.

16. Main Scenario: Button inside Table Row (line by line)

onViewProduct: function (oEvent) {
  const oButton = oEvent.getSource();      // 1. clicked Button
  const oContext = oButton.getBindingContext(); // 2. row address
  const oProduct = oContext.getObject();       // 3. real data
}
👆 Click a step.
Why does oButton.getBindingContext() work even though the button itself has no items="{...}"? Because contexts propagate down: Row has context → children inherit it.

17. Alternative via getParent() (and why shorter is better)

onViewProduct: function (oEvent) {
  const oButton = oEvent.getSource();
  const oRow = oButton.getParent(); // assumes parent IS the row!
  const oContext = oRow.getBindingContext();
  const oProduct = oContext.getObject();
}
Works only if parent really is ColumnListItem. If Button is wrapped in HBox/VBox, you need getParent().getParent(). XML change = broken code.
Preferred (cleaner): const oContext = oEvent.getSource().getBindingContext(); — independent of layout hierarchy.

24. Named Models: getBindingContext("products")

<Table items="{products>/Products}">
const oCtxDefault = oControl.getBindingContext(); // default (no name)
const oCtxNamed = oControl.getBindingContext("products");
Forgetting the name = #1 named-model bug. If binding is {products>...}, then getBindingContext() without name returns null. Names must match!

26. JSONModel vs OData V2/V4 (beginner-safe intro)

🗂️ JSONModel

  • Client-side object
  • oModel.getData() works
  • getObject()/getProperty() read local data
  • Great for learning

🌐 ODataModel (V2/V4)

  • Server-driven, async
  • Do NOT assume getData() exists same way
  • Context may need to load; use bindings + events
  • V4 contexts have different APIs in places
Don't assume oModel.getData() works for every model. For OData, rely on contexts/bindings, not raw data dumps.

31. Real-World CRUD: Product Management

Features: table + search + select + add/view/edit/delete + dialog.

XML View (sap.m.Table + Dialog) 
<Table id="tbl" items="{/Products}" mode="SingleSelectMaster" selectionChange=".onRowSelect">
  <headerToolbar><Toolbar>
    <SearchField search=".onSearch"/>
    <Button text="Add" press=".onAdd"/>
  </Toolbar></headerToolbar>
  <columns>... ID / Title / Price / Category / Actions ...</columns>
  <items><ColumnListItem><cells>
    <Text text="{id}"/><Text text="{title}"/>
    <Text text="{price}"/><Text text="{category}"/>
    <HBox><Button text="View" press=".onViewProduct"/>
    <Button icon="sap-icon://edit" press=".onEditProduct"/>
    <Button icon="sap-icon://delete" press=".onDeleteProduct"/></HBox>
  </cells></ColumnListItem></items>
</Table>
Controller.js 
onViewProduct: function (oEvent) {
  const oProduct = oEvent.getSource().getBindingContext().getObject();
  MessageBox.show(oProduct.title + " – " + oProduct.price);
},
onRowSelect: function (oEvent) {
  const oItem = oEvent.getParameter("listItem");
  const oProduct = oItem.getBindingContext().getObject();
},
onSearch: function (oEvent) {
  const sQ = oEvent.getParameter("query");
  // filter table binding by title
},
onDeleteProduct: function (oEvent) {
  const sPath = oEvent.getSource().getBindingContext().getPath();
  // remove /Products entry at sPath from JSONModel
}
Every handler follows the same rhythm: source → context → object/path → action. Toolbar Add/Search buttons have no row context — use byId/table binding there, not getBindingContext().
